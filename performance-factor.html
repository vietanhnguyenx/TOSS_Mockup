warningHow readings are grouped into flights — provisional One row is one flight; the Readings column counts the measurement points the vendor software produced for it, not the number of raw messages (the B787 fleet has recorded up to 65 messages on a single flight, against at most 5 readings after PET processes them). Grouping in this build still uses aircraft + date + flight number, which on the real dataset splits 50 flights in two and merges 4 pairs of distinct flights into one, because PEP’s DATE is the measurement date rather than the flight date. The settled rule (BR-PF-27) replaces that key: narrow the candidates by aircraft + flight number + route, then pick the flight whose midpoint is nearest the message time. Bản dựng chưa cài quy tắc mới vì cần bảng chuyến bay của hệ thống để lấy giờ cất và hạ cánh — xem BR-PF-30.

The specific-range deviation column has two names: PEP calls it DSR, PET calls it FM Dev. Same quantity, same unit, same formula.
Outlier rule (M2-6): two stages, applied per aircraft within the selected range. Stage 1 removes values beyond the absolute threshold ±15%; stage 2 removes values outside ±2σ around the mean of what remains. Both thresholds are system parameters (BR-PF-21), not constants in the source code — an administrator edits them at System Admin › System Parameters › Parameter Configuration, group Operations Analysis, where the existing Change History table already records old value, new value, who changed it, when and why. This screen only reads them. Excluded records are still stored, flagged Outlier, and left out of the average. Stage 2 is skipped when fewer than 3 readings remain.
Duplicate records ARE counted in the average; the Duplicate flag is for visibility only.
Green marks an aircraft performing better than the manufacturer baseline: DSR positive or PF negative. The two always carry opposite signs, so cells in the same row share one colour.
PF FMC is now computed for the Boeing fleet as well (BR-PF-14, settled 26/08). The missing FLHV column in the PET output is no longer an obstacle: the fuel heating value is a configuration parameter the analyst enters into the software, not a per-record measurement. The customer confirmed both PEP and PET run on the default 18590, so the correction −1,0221 is one constant shared by both branches.
Ghi chú: giá trị 18590 phải để ở dạng tham số cấu hình được, không viết cứng trong mã nguồn.

The two sample datasets do not overlap in time: the PEP (Airbus) branch covers 03–06/2026, the PET (Boeing) branch covers 07–08/2026. Both branches therefore appear together only from 07/2026 onward, where Airbus aircraft show as Inherited and Boeing aircraft as Calculated. This is a limitation of the sample data, not a business rule.

On the inheritance limit (BR-PF-09): the rule — warn once a value has been inherited for more than 6 periods — is implemented, but it cannot be triggered on this sample: the data spans only 6 months in total (03–08/2026), so the widest possible gap is 4 periods. The Stale badge will therefore not appear here. Nhãn cảnh báo quá 6 kỳ chỉ xuất hiện khi có bộ dữ liệu trải đủ dài — không phải lỗi dựng.

On the flexible From–To range (M3-2): Performance Factor is computed by the vendor software on a monthly period. When the selected range spans several months, the factor shown is the average of the period values inside the range — settled 25/08 as BR-PF-18, replacing the provisional reading carried by builds up to v0.15. It is an average of already-computed periods, not a recomputation from the raw readings.
